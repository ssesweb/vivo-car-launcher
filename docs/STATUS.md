# 当前状态与验证边界

更新时间: 2026-10-25。代码基线: v15 / versionName 1.5。

## 用户需求

1. 从手机选择应用，在 vivo 车载屏启动。
2. 底部操作区正确避让车机 dock。
3. 需要时能够全屏。
4. 不自动左右翻动车机页面。
5. 未连接电脑或车机时，也能准备 Shizuku 授权及后台服务。

## 当前验证

| 项目 | 结果 | 边界 |
| --- | --- | --- |
| 应用枚举 | 测试设备显示 158 个应用 | 数量随设备变化，不代表均可投屏 |
| Shizuku 服务 | ADB 启动成功，UID 2000 | 不代表 root 权限 |
| 车启授权 | 检测到既有授权 | 本轮未重新走首次授权弹窗 |
| UserService | 绑定成功并可拉起守护进程 | 测试时已连接车机 |
| 取代旧 ADB 守护进程 | 停止旧进程后恢复，PING 返回 PONG uid=2000 | 旧看门狗已暂停 |
| 关闭车启 | 强制停止车启后，后台 PING 仍正常 | 不等于经历系统重启 |
| 后台进程恢复 | 终止 UserService 进程，再打开车启成功恢复 | 需要 Shizuku 仍在运行 |
| 不自动翻页 | v14 起移除应用侧 LAUNCHICON 调用 | 守护进程保留旧调试协议，见结构文档 |
| 安全区 | v13 原生图标点击路径的番茄冷、热启动曾成功 | v15 使用直接启动，需要重新验收 |
| 按需全屏 | 未完成 | 窗口标记 fullscreen 不等于画面无 dock 遮挡 |
| 未连车授权 | 代码不依赖车载屏检测即可准备授权 | 本轮未物理断开车机验证 |

## 版本沿革

- v6: 通过包可见性配置修复部分应用在列表中缺失。
- v7: 增加图标、搜索及排序。
- v8: 补充 INTERNET 权限，使本机 socket 通信可用。
- v9: 尝试根据车载虚拟屏选择启动目标。
- v10-v12: 尝试截屏匹配图标后真实点击，遇到图标渲染和超时问题。
- v13: 修复图标透明留白，番茄原生点击路径冷、热启动成功。匹配误差由 0.267 降到 0.131，原阈值为 0.15。
- v14: 按用户要求移除自动翻页找图标，恢复直接启动。
- v15: 接入 Shizuku 授权、UserService 和后台恢复，去除应用侧遗留图标扫描实现。

## 后续重点

先确认直接启动的内容安全区，再完成按需全屏。两项都应以真实画面和可操作区域验收，不以命令 exit=0 或 Task 的 fullscreen 字段作为完成依据。
